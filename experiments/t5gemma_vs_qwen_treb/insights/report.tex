\section{What we learned}

\textbf{Upstream bug caps T5Gemma 2 at 4K input tokens}, not 128K. At \texttt{batch\_size=1}, \texttt{eager} attention, inputs $>4094$ tokens raise \texttt{RuntimeError: size of tensor a (4097) must match tensor b (N)}. Constant $4097 = 4\times\text{sliding\_window}(1024)+1$; $N=\text{input\_length}+3$. \texttt{sdpa} same class; \texttt{flash\_attention\_2} explicitly unsupported. Filed \href{https://github.com/huggingface/transformers/issues/45521}{\#45521}; FA2 feature request filed \href{https://github.com/huggingface/transformers/issues/45522}{\#45522}.

\textbf{Base T5Gemma 2 never learned to stop.} On plain ``Q: 2+2? A:'' it outputs \texttt{4} (correct), then loops \texttt{Q: 2+2? A: 4} until \texttt{max\_new\_tokens}. EOS is not reliably emitted. On TCoT-format prompts it outputs nothing at all --- the instruction format is OOD for this pretrained checkpoint (Google didn't release an IT variant). This is a pretrained-model property, not something our SFT introduced.

\textbf{Our FLAN-SFT adapter traded content for format.} Training loss $3.22\!\to\!1.47$ over 782 steps on 100K FLAN samples --- real learning, but mediocre plateau (smoke-test overfit on 200 samples got to 0.32). At inference: always emits one $\{\text{``answer''}: N\}$ JSON then loops.

So SFT gained: always commits to JSON envelope. SFT lost nothing structurally (EOS was already broken). What SFT never gained: content understanding on anything beyond single-scalar answers. Not mode-collapse in the ``weights are random'' sense --- the number $100$ for a \$101 problem shows task-weak correlation --- but mode-collapse in the ``learned shape, not semantics'' sense.

\textbf{Qwen 2.5 7B Instruct works end-to-end via vLLM.} 7{,}789 TReB English samples, full 32K context, $\sim$7 min wall-clock, $\sim$\$1 on 1$\times$~H100~NVL.

Reading these requires care: spot-checks show Qwen produces multi-paragraph step-by-step reasoning but rarely wraps the final answer in \texttt{\{"answer": \ldots\}}. Tasks with EM=0 and ROUGE=0.3--0.5 (Understanding, Title\_Naming, Summary) are format-not-capability failures. The judge's 12-class failure-mode taxonomy will disentangle these; judge run deferred until the SFT is usable.

\textbf{Pipeline hardening shipped during this session:}
\begin{itemize}\setlength\itemsep{0pt}
  \item Incremental \texttt{.partial.jsonl} writes with \texttt{fsync} every 5 batches --- saved 95/100 after a crash where previously we lost everything.
  \item Token-budgeted prompt assembly (\texttt{build\_prompt\_tcot}): guarantees question + format-instruction survive. Previously right-truncation silently dropped the question on 12\% of samples ($\geq$2K tokens) --- 1-in-8 old predictions were answered without the model seeing the question.
  \item \texttt{merge\_adapter.py} auto-infers base from \texttt{adapter\_config.json} (prevents \texttt{PeftModel.from\_pretrained} silent-corruption when the hand-typed base doesn't match training).
  \item Sentinel (\texttt{predictions.jsonl.done}) + \texttt{monitor\_pod.sh}: on sentinel detection, scp~$\to$~verify line count matches sentinel~$\to$~\texttt{DELETE} pod. No sentinel = pod stays alive for diagnosis.
\end{itemize}

\section{What's next}

\textbf{T5Gemma needs a re-SFT} to be useful for this comparison. Priority fixes, in order:
\begin{enumerate}\setlength\itemsep{0pt}
  \item \textbf{Fix EOS.} Audit FLAN tokenization --- append a proper EOS token to every training target. This is likely why both base and SFT loop. Highest leverage.
  \item \textbf{Use reasoning data.} FLAN targets are mostly short scalar answers; model never learned to reason. Train on FLAN-CoT / StrategyQA / GSM8K with full reasoning traces, not just final answers.
  \item \textbf{More epochs.} Eval loss $1.38$ at 782 steps is undertrained.
\end{enumerate}

\textbf{Without waiting for a new SFT}, we can run Qwen@4K (client-side truncated) against T5Gemma base on the 100 stratified samples. Won't answer ``does SFT help encoder-decoders?'' but will answer ``does architecture matter pre-IT?'' --- honest, narrower result.

\textbf{Upstream dependency.} Both transformers issues need to land before T5Gemma 2's advertised 128K context is reachable via HF. Related Gemma-family issues historically resolved on 1--6~week timelines.
